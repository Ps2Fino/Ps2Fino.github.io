# Swipe navigation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A horizontal swipe moves between the Knights, Knaves, and Go pages with the page following the thumb, and swipes past the ends do nothing.

**Architecture:** `Home` becomes a track of three panels, one per tab, in `Home`'s own CSS module; `.PageContainer` stays as the fixed shell for the QR and 404 pages. A hook reads the touch, translates the track with the finger, and on a committed swipe calls App's existing `switchView`, so narration stop, sheet close, and tab move stay written once and are shared with the bottom bar's taps.

**Tech Stack:** React 18 (Create React App), TypeScript 4.9, CSS modules, MUI v5, react-router 6, Jest + React Testing Library, pointer events, `inert`.

**Spec:** `docs/superpowers/specs/2026-11-18-avalon-swipe-navigation-design.md`. The picker-scale spec (`docs/superpowers/specs/2026-11-18-avalon-picker-scale-design.md`) holds the grid geometry the strip must not move, and the device checklist (`docs/superpowers/plans/2026-11-16-device-checklist.md`) is the gate the narrator work used.

-   jsdom has **no `PointerEvent` constructor** (checked: `'PointerEvent' in jsdom.window` is false), so `fireEvent.pointerDown(el, {clientX, pointerType, pointerId, timeStamp})` produces a plain `Event` and React's handler sees `clientX`, `pointerType`, and `pointerId` as **undefined** — measured in this repo, against React 18.2 and `@testing-library/dom` 7.x, by a scratch test that was then deleted. The tests must build their own events: `new Event('pointerdown', {bubbles: true, cancelable: true})` with `Object.defineProperty` for `pointerId`, `pointerType`, `clientX`, `clientY`, and `timeStamp`, then `target.dispatchEvent(event)`. Measured: React's `onPointerDown` and `onPointerMove` fire from that event and read all five properties, including `timeStamp` (a real `Event`'s own `timeStamp` is the epoch clock, so the hook's velocity must come from the events' `timeStamp` values, never mixed with `performance.now()`). jsdom has no `ResizeObserver`, so `useTrackWidth` must return 0 when it is undefined.
-   `touch-action` is the **intersection** of the values from the touch target up to the root: a `none` on an ancestor kills a `pan-y` on a child. So the shell's `touch-action: none` (`src/App.css:22` on `.App`, `:31` on `.AppContainer`, and `src/index.css:9` on `body`) becomes `pan-y` at all three, the track carries `pan-y`, and the horizontal axis is captured by the hook. This is the one place the design's line "the `touch-action: none` stays" cannot hold: with `none` above the panels, the Go panel cannot scroll, and `Narrate` is a scroll away from the cast grid at 390px (measured in the picker-scale plan, Task 2 Step 4). **The author's ruling, in this run:** `src/index.css`'s `body` rule changes too, because the plan's CI gate counts `touch-action: none` in the built CSS as 0, and `pan-y` at `body` keeps horizontal body pans and pinch-zoom blocked while `overflow: hidden` and `overscroll-behavior: none` stay. **Corrected in this run, from real-touch measurements on the served build (controller and Task 3 reviewer, CDP `Input.dispatchTouchEvent`):** `.PagePanel` also carries `touch-action: pan-y`. A scrollable panel with the default `auto` hands the touch to the compositor: a horizontal drag over it gets `pointercancel` after 2 moves, so `useSwipeNav` snaps back and commits nothing; with `pan-y` on the panel the same drag keeps its pointer (10 moves, `pointerup`, commit). And the strip needs a **clip element that does not move**: `transform` on a fixed, clipping element moves its clip window off the viewport, so at tabs 1 and 2 the content area paints blank and `elementFromPoint` in the middle of the screen returns `AppContainer` — no touch reaches the panel, so no swipe can start. `.PageClip` is the fixed element with `overflow: hidden` and `width: 100vw`; `.PageTrack` is the flex row of the three panels inside it (`width: 100%`, panels `flex: 0 0 100%`), and carries the `transform`.

```ts
// src/views/Home/pointer-events.ts
/** One pointer event jsdom cannot build: a plain Event carrying the pointer props. */
export function pointerEvent(
    name: 'pointerdown' | 'pointermove' | 'pointerup' | 'pointercancel',
    x: number,
    timeStamp: number,
    opts: {pointerId?: number; pointerType?: string} = {},
): Event {
    const event = new Event(name, {bubbles: true, cancelable: true})
    const props = {
        pointerId: opts.pointerId ?? 1,
        pointerType: opts.pointerType ?? 'touch',
        clientX: x,
        clientY: 300,
        timeStamp,
    }
    for (const key of Object.keys(props)) {
        Object.defineProperty(event, key, {
            value: props[key],
            configurable: true,
        })
    }
    return event
}
```

-   Produces, the hook Task 3 wires into `Home`:

```ts
export function useTrackWidth(ref: RefObject<HTMLDivElement>): number

export function useSwipeNav(
    tab: number,
    commit: (direction: 1 | -1) => void,
    width: number,
): {
    bind: {
        onPointerDown: (event: PointerEvent<HTMLDivElement>) => void
        onPointerMove: (event: PointerEvent<HTMLDivElement>) => void
        onPointerUp: (event: PointerEvent<HTMLDivElement>) => void
        onPointerCancel: (event: PointerEvent<HTMLDivElement>) => void
    }
    transform: number
    dragging: boolean
}
```

`transform` is `-(tab * width) + dragX`, in px, the value Task 3 puts on `.PageTrack`. The constants are `AXIS_LOCK = 10` (px before the dominant axis is fixed), `COMMIT_DISTANCE = 120`, `FLING_DISTANCE = 60`, `FLING_VELOCITY = 0.6` (px per ms), `END_PULL = 60`, `FIRST_TAB = 0`, `LAST_TAB = 2`. **The author's ruling, in this run:** the end offset saturates at 60px (`END_PULL`), not a proportional 0.3. A proportional 0.3 cannot satisfy the mid-drag assertion below (`40px` → `40`), so the design's "0.3 at the ends" is expressed as the pull saturating at 0.3 of a 200px drag. The offset's sign follows the drag's sign, so the blank gap appears on the side being swiped towards. `useTrackWidth` observes the ref's `clientWidth` with `ResizeObserver` when it exists, and returns 0 when it does not (jsdom), so the hook's math never divides by an unmeasured width.

```ts
const commit = |dragX| >= COMMIT_DISTANCE || (|dragX| >= FLING_DISTANCE && |velocity| >= FLING_VELOCITY)
const direction = dragX < 0 ? 1 : -1
```

Then `tab + direction` inside `[FIRST_TAB, LAST_TAB]` calls `commit(direction)`; outside it, nothing. The transform is the tab's offset plus the drag, resisted at an end:

```ts
const direction = dragX < 0 ? 1 : -1
const atEnd =
    (tab === LAST_TAB && direction === 1) ||
    (tab === FIRST_TAB && direction === -1)
const offset = atEnd
    ? Math.sign(dragX) * Math.min(Math.abs(dragX), END_PULL)
    : dragX
const transform = -(tab * width) + offset
```

Velocity is `(lastMoveX - downX) / (lastMoveT - downT)`, from the pointer-down record and the last pointer-move. Read the stamps from `event.nativeEvent.timeStamp`: React copies `timeStamp` as `event.timeStamp || Date.now()`, so a test event stamped `0` reads as the epoch clock through the synthetic event. `pointercancel` and a pointer id that is not the active one reset `dragX` and `axis` without calling `commit`. `onPointerMove` calls `event.preventDefault()` once the axis is locked horizontal, which is what stops a tile's tap on a swipe. A comment in the file names the four thresholds and the end pull.
